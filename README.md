# Picrete Studio — dev.picrete.com

Отдельная платформа, где преподаватели создают и итеративно улучшают ИИ-ассистентов для своих дисциплин
(неорганическая, коллоидная, аналитическая, физическая химия, разделы физики).

## Возможности

- **Провайдеры моделей** — DeepSeek V4.1 Flash (`deepseek-flash`) используется для генерации, независимого решения, предметного
  аудита и разбора со студентом. Старые Flash и экспериментальные модели advisory доступны только для экспериментов и не
  могут принимать решения о допуске задач. Ключи хранятся в БД зашифрованными (Fernet от
  `STUDIO_SECRET_KEY`). Также поддерживаются Yandex AI Studio, Alibaba Model Studio и OpenAI-совместимые API.
- **Ассистент дисциплины** — профиль (темы, аудитория, описание), критерии оценивания с баллами,
  «нюансы» — экспертные тонкости проверки, которые модель сама не знает.
- **Промпты с версионированием** — системный промпт генерируется моделью-архитектором из профиля по
  best-practices и рекомендациям конкретного семейства (DeepSeek V4: thinking по умолчанию, сэмплинг
  игнорируется; Qwen: RU-принуждение, финальное напоминание; YandexGPT: temperature 0–1, компактность;
  GPT-5.5: без temperature, только reasoning_effort). Версии активируются, сравниваются и откатываются.
- **Автоматический выпуск задач** — типизированный блюпринт → structured chemistry facts → детерминированная
  проверка предметного инварианта → два независимых решения DeepSeek V4.1 Flash → предметный критик → проверка
  источников, рубрики и дубликатов. Успешные задачи сразу готовы; преподавателю показываются только адресные
  исключения. При отбраковке генератор автоматически восполняет партию.
- **Сценарии проверки работ** — распознавание DataLab → основная проверка → независимый аудит → сверка
  итогового балла и каждого критерия. Одна production-модель может работать в двух разных ролях с независимыми
  инструкциями; самооценка confidence не участвует в решении.
- **Playground** — проверка задачи, OCR и диалога без создания контрольной в Picrete. Сравнение моделей и
  экспертная разметка остаются необязательным калибровочным стендом, а не ручной операцией над каждой работой.

JSON-контракт проверки совместим с production-платформой `Picrete` (`ai_grading.rs`). Поле `confidence`
сохраняется для обратной совместимости и диагностики, но не является доказательством качества.

## Структура

```
backend/   FastAPI (Python 3.12), SQLAlchemy async, Postgres (dev: SQLite)
frontend/  React 19 + TS strict + Vite + Tailwind, дизайн-токены «лабораторного журнала»
deploy/    nginx-конфиг для dev.picrete.com
```

## Локальный запуск

```bash
cd backend
python3.12 -m venv .venv && ./.venv/bin/pip install -e .
./.venv/bin/uvicorn app.main:app --port 8100        # SQLite ./data/studio.db, admin/admin

cd ../frontend
npm install && npm run dev                            # http://localhost:5174, proxy /api → 8100
```

## Деплой на сервер (тот же хост, что picrete.com)

1. БД: `CREATE DATABASE picrete_studio OWNER picretesuperuser;`
2. Бэкенд: скопировать репозиторий, создать `.env` рядом с `docker-compose.yml`
   (см. `backend/.env.example`; обязательны `STUDIO_SECRET_KEY`, `STUDIO_FIRST_ADMIN_PASSWORD`,
   `POSTGRES_PASSWORD`, `STUDIO_DATALAB_API_KEY`), затем `docker compose up -d --build`.
   API слушает 127.0.0.1:8100 (network_mode: host).
3. Фронтенд: `cd frontend && npm ci && npm run build`, выложить `dist/` в `/var/www/picrete-studio`.
4. nginx: `deploy/nginx-dev.picrete.com.conf` → `/etc/nginx/sites-enabled/`,
   `certbot --nginx -d dev.picrete.com`, `nginx -s reload`.
5. Зайти на https://dev.picrete.com, сменить пароль администратора, добавить провайдеров и ключи через UI.

## Порядок работы преподавателя

1. «Провайдеры» → подключить Яндекс/DeepSeek/Qwen (+ OpenAI как архитектора).
2. «Ассистенты» → создать дисциплину → заполнить профиль, критерии, нюансы.
3. «Промпты» → сгенерировать v1 архитектором под целевую модель → активировать.
4. «Задания» → выбрать типизированный блюпринт → запустить автоматическую партию → разобрать только исключения.
5. «Проверка» → создать рекомендуемый сценарий и прогнать фото или текст решения без контрольной в Picrete.
6. Увидели систематическую ошибку → добавить нюанс в профиль → перегенерировать промпт (v2) → снова
   сравнить. Итерации и вердикты сохраняются в истории.


## Согласованный выпуск

Релиз собирается из чистых коммитов `main` Picrete, Studio-Picrete и Front-Picrete.
SHA всех трёх репозиториев записываются в общий `release-manifest.json` рядом с
каталогами выпуска на сервере. Собранные файлы не редактируются вручную.
API публикуют свой SHA через `/version`, frontend — через `/build-info.json`.
Изменения контракта Studio → Picrete проверяются вместе с обоими интерфейсами.

Перед публикацией проходят проверки `.github/workflows/verify.yml`.
Секреты, пользовательские данные, каталоги банка и артефакты проверки не коммитятся.

## Отработка Свиридова и перенос проверки в Picrete

Playground → «Банк Picrete · Свиридов» → привязанный курс → поиск номера/текста.
Список читается из банка основного Picrete и содержит только задания с полным
эталоном. Ответ вводится текстом. Режим «Черновик» передаёт текущий снимок в
production-движок Picrete; «Опубликованная» читает действующий снимок курса.
Результаты и экспертные оценки сохраняются в истории, ответы можно повторять.
Проверьте верный, частичный и ошибочный ответ; после правок повторите их.

«Курсы» → «Опубликовать обновление» переносит профиль, активный grader/tutor и
канонические студенческие справочники. Публикация grader требует успешного
прогона текущего снимка, отмеченного «Проверка корректна». Правки профиля,
модели, промптов и справочников меняют хэш и требуют нового прогона.

Picrete worker использует опубликованный grader и ту же модель/профиль, что
preview. Новые задания из банка получают опубликованную шкалу критериев;
существующие работы сохраняют свою рубрику. Отдельные экспериментальные
сценарии Studio («Сравнение моделей», произвольные pipelines) не публикуются
как граф исполнения в Picrete. Фото/OCR проверяется отдельно; рисунки условия
доступны преподавателю, но текстовая модель не видит их пиксели.

Проверка включается отдельно в профиле ассистента; у остальных дисциплин по умолчанию выключена.
Старые снимки без `assistant.grading_enabled` сохраняют прежний режим. Новая
публикация с активным grader включает общий движок. Модель должна совпадать с
`ASSISTANT_AI_MODEL`; ключи остаются на сервере и не входят в снимок.
Preview не создаёт попыток, работ или студенческих оценок. Метаданные реальной
проверки сохраняют модель, версию снимка и grader-промпта.

DeepSeek V4.1 Flash Preview: `deepseek-v4.1-flash-expires-on-0910` — временная
экспериментальная модель; доступность подтверждена API 08.09.2026. Не входит
в allowlist итоговых решений. Для существующего провайдера добавляется через
«Провайдеры», семейство `deepseek`; новые подключения получают её в preset.
