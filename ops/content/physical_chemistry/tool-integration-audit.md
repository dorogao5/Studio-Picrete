# Инструменты тренажёра: границы и проверка

Дата: 2026-09-12. Пакет: предоставленный `essential_skills` 1.0.0,
адаптированный шлюз v2. Исходный каталог не изменяется.

## Что меняется

Роль модели сохраняется: генератор строит задачу; единственный независимый
верификатор проверяет и исправляет эту же задачу. Калькулятор, SymPy и справочник
— вызываемые моделью инструменты, не дополнительные модели или классификаторы.
Помощник и проверка работы студента получают эталон, но не раскрывают будущие
ответы в режиме пошаговой помощи. Четыре разрешения на инструменты независимы
и по умолчанию выключены; включение физхимии не меняет настройки других курсов.

## Проверенные ограничения

- Числа Decimal читаются из исходной записи, не через float; результат сохраняет
  34 значащие цифры без преждевременного округления.
- SymPy получает объекты из ограниченного AST, не строковый `sympify`/`eval`.
  Недоказанное тождество не означает ошибку решения; область определения
  и химическая применимость остаются предметом анализа модели.
- Расчёт идёт в отдельном процессе с ограничением времени и ресурсов.
  Неверные аргументы возвращаются в тот же диалог для исправления, а не запускают
  генерацию другой задачи. Сетевой сбой не считается химической ошибкой.
- Приватный CSV отсутствует в Git и образе. Подключается read-only; справочник
  возвращает происхождение и SHA256 именно прочитанных данных.
- Исходные 80 записей сохранены без изменения чисел. Это проверка сохранности,
  **не независимая сертификация всех справочных значений**. Ошибочная пометка
  брома как моноизотопного элемента отмечается отдельным предупреждением.
- Секрет доступа известен только серверу. В браузер не передаются ключ,
  внутренние трассы, рассуждения модели и полный справочник.

## Выпуск

Предварительные проверки: 54 теста шлюза, включая сохранность приватной таблицы;
Linux-контейнер non-root/read-only/cap-drop/network-none — четыре параллельных
расчёта и восстановление после ограничения ресурсоёмкого выражения. Лимиты
контрольного контейнера: 2 CPU, 2304 MiB, 32 процесса. Проверки Studio: 581
backend/ops-тест и 23 frontend-теста; Rust: 30 тестов транспорта, помощника
и проверки решений. Эти результаты относятся к локальному прогону перед выпуском.

Локальные тесты инструментов и транспортные тесты с имитацией API сами по себе
не доказывают качество Qwen/DeepSeek. До включения необходим реальный контроль
цепочки «вызов → результат → окончательный ответ», затем предметная проверка
новой задачи и проверка пошаговой помощи студенту. Сведения о реальных проверках
фиксируются по результату, без обещания абсолютной безошибочности модели.

## Qwen continuation: измерения 2026-09-12

Узкая правка транспорта удаляет `reasoning_content` только из возвращаемого
Qwen assistant-сообщения в следующем запросе. Thinking модели не выключается;
`role`, `content`, `tool_calls` и их ID сохраняются. DeepSeek продолжает получать
свой reasoning в памяти диалога; в audit он не записывается.

Проверки использовали реальный streaming adapter, Yandex Qwen3.6-35b-a3b,
локальный authenticated hardened HTTP gateway, calculator v2 / SymPy v2.
JSON Schema и `tool_choice=auto` сохранялись. Это отдельные пробы, не строгий
парный A/B-эксперимент; единственная причина повторов ими не установлена.

значения сохранялась, однако соответствие конкретной инструкции final не прошло.
В диагностических пробах после второго нежелательного tool call дальнейшие
платные запросы не отправлялись. Tokens в таблице включают оба реально выполненных
LLM-запроса, в том числе последний, остановленный диагностической обёрткой.

Итог: частичный положительный эффект, **не устранение повторов и не 3/3 успешных
проверки всех инструментов**. Включение tools остаётся на hold. Новые классификаторы,
автоматическая смена модели, отключение thinking и скрытая генерация замены
не добавлены. Приватные JSON artifacts сохранены вне Git, без ключей и reasoning;
данный раздел не содержит полной справочной записи или таблицы.

## Последующая доводка контракта

Для включённых инструментов генератора и проверяющего первый запрос использует
`tool_choice=required`, дальнейшие — `auto`. У помощника и проверки студенческого
решения остаётся `auto`: подсказка первого шага не требует искусственного расчёта.
Это исполнение инструмента, не дополнительный оценщик или фильтр допуска.

Calculator v3 возвращает `unit:null, unit_inference:not_performed`: арифметика
не выводит физические размерности. Изменение версии отличает новые trace от v2.
Примеры Аррениуса согласованы с блюпринтом: студент находит E_a и k при третьей
температуре; оба результата независимо проверены локальной Decimal-арифметикой.

В реальном `run_tutor_reply` три сценария — округление ln(34.38), производная
концентрации первого порядка и lookup R — завершились одним вызовом соответствующего
инструмента и ответом (4.85 / 4.21 / 3.11 с). Будущие ответы не раскрывались.
Это три контрольных случая, не статистическая гарантия.

Проверка той же задачи с намеренно внесённой ошибкой ×10 в конечном ответе дала
полную исправленную задачу с неизменным условием: DeepSeek, пять calculator-v3
вызовов одним пакетом, два модельных запроса, 97.46 с, 21934 токена. Исправлены
и промежуточные строки. Ошибка была внесена для QA, не сгенерирована моделью.

При пустом final после успешного вычисления адаптер один раз продолжает тот же
диалог с сохранёнными данными и tool results, `tool_choice=none`. Вычисления не
повторяются, новая задача не создаётся. Повторно пустой ответ, сетевые ошибки,
отказы и пустой ответ до успешных вычислений не запускают новую генерацию.
Продолжение учитывается в usage и укладывается в общий deadline.

На реальной новой задаче Аррениуса такое завершение сработало: 32.95 с, четыре
модельных запроса, два расчёта, одно завершение, 39169 токенов. Получены правильные
E_a=74999.4127198212 Дж/моль и k320=0.16373040843134 с⁻¹ по исходным данным.
В тексте генератора оставались неточные последние цифры отдельного логарифма.
Независимый verifier получил правильный логарифм инструментом (четыре вычисления,
два запроса, 34.36 с, 17094 токена), но оставил corrected_task=null.
Поэтому обновлён контракт: в режиме tools verification.solution/answer — полный
проверенный учебный эталон и чистый ответ. При pass они сохраняются в той же задаче,
даже если отдельный corrected_task не понадобился. Исходный fingerprint проверяется
до применения; условие, rubric, ID не меняются. Tools-off поведение прежнее.

Одна предыдущая диагностическая обёртка ошибочно повторно вызвала verifier при
импорте helper; её следующая генерация завершилась пустым final, usage генерации
не сохранился. Эти данные не учитываются как успешная проверка или нулевая стоимость.
Импорт исправлен; последующие пробы сохраняли usage и не меняли БД.

Записанные здесь модельные пробы выполнены на реальных Yandex-моделях с локальным
закрытым gateway. Они не подменяют отдельную проверку опубликованной студенческой
цепочки после deployment. Абсолютная безошибочность модели не заявляется.
